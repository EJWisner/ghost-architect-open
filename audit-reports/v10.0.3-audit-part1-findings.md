## CATEGORY 1: CONVERSION KILLERS (ranked by revenue impact)

**CK-1. README privacy section is factually false on the exact surface security teams are invited to verify.**
README.md:559 states "No telemetry, no analytics, no phone-home." Reality: src/telemetry/pulse.js:70 (pingModeUsage) POSTs a persistent UUID, version, tier, and mode to signup.ghostarchitect.dev on every mode run (wired at bin/ghost.js:2283, 2289, 2503, 2554), default-on, opt-out via GHOST_NO_PING=1 which the README never documents. README.md:561 then invites reviewers to "read every line and verify these claims yourself." The pulse implementation is genuinely privacy-conscious (no code, no findings, hashed identifiers); the copy is what fails the review. One discredited claim poisons the entire privacy section, and Ghost Open's whole enterprise role is the security-team gate-pass.
Fix: rewrite the bullet honestly and document GHOST_NO_PING. Effort: S.

**CK-2. The shipped LICENSE file contradicts the README license section; the free tier has no written legal grant.**
LICENSE:1-19 is an all-rights-reserved proprietary notice ("Unauthorized use... strictly prohibited"), stamped "Ghost Architect v1.7.0, March 18, 2026." README.md:936-940 claims BUSL-1.1, free for personal and small-team use, GPL v3 conversion after 4 years. README.md:947-948 then contradicts its own license section six lines later. package.json says "SEE LICENSE IN LICENSE." Procurement and OSS-compliance scanners read the LICENSE file, conclude "no license," and can auto-block adoption.
Fix: pick one story; if BUSL-1.1, ship real BUSL text with the Additional Use Grant and reconcile the README footer. Effort: S-M.

**CK-3. The trial-to-paid funnel is broken at its highest-intent moment: day 8 is a brick wall with no trial-aware messaging, and the fallback Open experience is pre-burned.**
Three verified parts:
(a) A lapsed license in hard_stop blocks the entire CLI via process.exit(1) (src/license/validator.js:208, bin/ghost.js:2189-2193), including Question, Recon, and the free quota that a never-trialed user gets. The red box never mentions the existing path back to Open (ghost --deactivate). The trial makes the product strictly worse than never trialing.
(b) All four expiry-state messages say "Renew" (validator.js:188-203); none branch on payload.tier === 'trial' even though the data is in hand, and trialDaysRemaining() (session.js:31) has zero consumers. A trial user is never told what they are about to lose or given a subscribe CTA distinct from a renewal notice.
(c) incrementScanCount has no tier guard (src/freemium.js:105-110) and reports.js:409 calls it on every tier, so 4+ scans during the trial pre-exhaust the Open quota; the post-trial downgrade path opens on "You've used your 4 free Ghost Architect™ reports."
Fix: on hard_stop for trial (and arguably all tiers), degrade to Open behind a conversion banner; trial-branch the four messages and print a per-run day-count; guard the counter to Open only. Effort: M. Note: verify trial grace_until behavior against signup-worker; if trials get the paid ~5-day grace, the "7-day trial" is really ~13 days.

**CK-4. Interactive profile creation, the white-label headline feature for the paying tiers, crashes or silently discards input on every use; the correct implementation is dead code.**
runProfileWizard() returns a profile object and never writes to disk (src/profile/wizard.js:13-15, :234), but both live handlers treat the return as a saved file path: bin/ghost.js:2348-2359 and 3074-3089 do `loadProfile(savedPath)`. Answering the default-Yes "Use this profile for this session?" throws a TypeError presented as "This is a Ghost Architect bug"; answering No discards the entire wizard session. Meanwhile the complete, correct profiles menu (create with writeProfile, edit, delete, set-default, hardened editor launcher; bin/ghost.js:664-903) is unreachable: the dispatch at :2294 tests a value ('profiles') that no menu ever returns. There is currently no UI path to edit or delete a profile at all. Only headless --create-profile works.
Fix: route both menu entries to runProfilesMenu() and delete the two broken inline handlers; this fixes creation, restores edit/delete, and removes ~200 duplicated lines. Effort: S.

**CK-5. README tier matrix hides the Open tier's 4-scan quota.**
README.md:572-576 shows unqualified checkmarks for POI, Blast, Conflict, and Prompt Triage on Open, and :606 says the free tier is "fully featured." All four are 'quota' gated at 4 scans per install (tier-gates.js:59-62, :102). The matrix already knows how to express quotas (Commit Forecast reads "1 free / install"). An evaluator hits the paywall on scan 5 mid-evaluation and reads the README as bait-and-switch.
Fix: matrix cells "4 free scans / install"; qualify "fully featured." Effort: S.

**CK-6. Prompt Triage silently degrades to regex-only analysis for 11 of the 15 marketed target models.**
Every Tier 2/3 detector passes opts.targetModel directly as the model id on the Anthropic API (src/prompt-pack/llmAuditClient.js:454-461; the doc comment at :492-493 says "Must be a Claude family model" but nothing enforces it). Picking GPT-5, Gemini, Llama, Mistral, or Qwen from the 15-model picker 404s every LLM call, which fail-open to zero findings; the report still lists all 16 detectors as run. The failure warning only prints at process exit (llmAuditClient.js:164-173, no in-mode call site), and the cost pre-flight prices "GPT-5" at Sonnet rates via the silent getPricing fallback. A user auditing a GPT-5 prompt library (a core marketed use case) gets a shallow report and concludes the product is shallow.
Fix: run the audit call on a fixed Claude model and use targetModel only for tokenizer/context math (or hard-skip Tier 2 for non-anthropic families with a visible note at scan start); call emitTier2FailureWarning() right after the scan loop; fix the estimate label. Effort: M.

**CK-7. The Inheritance Audit sells license-risk detection that is dead code.**
classifyLicense() is never called (single grep hit is its definition); all six manifest parsers hardcode licenseRisk 'unknown' (src/modes/audit/dependencyMap.js:71-95, 112-260), so the copyleft/commercial callouts (:368-386) are unreachable and a repo full of AGPL dependencies produces "No license, EOL, or commercial-dependency risks detected" (reportBuilder.js:297). The Open paywall (:71) and the Methodology section (reportBuilder.js:385) both sell exactly this capability. This is the risk class a PE-diligence buyer is paying to catch.
Fix: wire real license lookup, or change report and paywall copy until it exists. Effort: M (copy fix S).

**CK-8. The npm page opens with roughly 135 lines of changelog before the product pitch.**
README.md:5-137 is version notes (crash fixes, trial funnel fixes) before the first sentence of what Ghost is at :139, with more version strata at :180-345. The first screen a buyer sees is an instability résumé. Fix: pitch, install, modes, tiers first; one short recent-releases block linking to CHANGELOG.md. Effort: M (mostly deletion).

## CATEGORY 2: CUSTOMER EXPERIENCE GAPS

**CX-1. "(Pro Max or higher)" is wrong for Team and Enterprise customers.** Ghost Brief and Executive Brief are Max-variant-only (tier-gates.js:66), but menu labels (bin/ghost.js:470, 477), help (:309), and headless --brief (:3204) all say "Pro Max or higher." A $399 Team customer reads this as a broken license. The watcher already has the correct phrasing ("requires Max tier," watcher-commit.js:1802). Fix: standardize. Effort: S.

**CX-2. Ghost Watcher onboarding traps and oversells.** (a) The Enable Watch wizard has no cancel path across 8 required prompts including the GitHub PAT; the only escape is Ctrl+C, which kills the whole session (bin/ghost.js:2824-2915). (b) Watch Status and Disable Watch advertise "(or 'back' to cancel)" and validation accepts it, but the cancel check tests the sentinel, not the typed keyword (isBack vs isBackKeyword, bin/ghost.js:2973, 3016), so typing back marches the user into the PAT prompt and then errors. (c) The scan picker pre-checks Ghost Brief for plain-Team users whose tier silently skips it in CI (bin/ghost.js:2855-2864 vs watcher-commit.js:1798-1802): the promised brief never appears and nobody says so at setup. Fix: accept 'back' on the repo prompt; fix the predicate at both sites; disable or annotate the Brief checkbox for non-Max. Effort: S each.

**CX-3. Infrastructure errors are presented as evidentiary doubt inside the deliverable.** An LLM-verifier call failure becomes verdict 'partial' carrying the raw error string (llm-verifier.js:134-136), which verifier.js:461-467 stamps into the report as "[UNVERIFIED]" plus an inline "LLM verifier call failed: 429 rate_limit..." blockquote on every affected finding. A rate-limit burst mid-verification defaces the whole PDF. Fix: retry once; on persistent failure keep the regex-pass verdict and add one report-level note; never inline error text into finding prose. Effort: S.

**CX-4. Executive Brief invents economics.** The "Remediation Cost Comparison" table derives "AI-assisted" cost as manual-hours x $0.15 and AI hours as 10 percent of manual (executive-brief.js:100-102, rendered :263-282), and manual cost hardcodes $200/hr instead of configured rates. A 6,700x savings claim in a board-facing PDF is indefensible and taints the rest of the report. Related: the health score's per-band caps make 20 criticals score identically to 2 (executive-brief.js:20-33), and the narrative model is hardcoded to claude-sonnet-4-6 ignoring the user's default (:140). Fix: configured rates; drop or footnote the AI row as an assumption; rescale or floor the critical band. Effort: S.

**CX-5. Audit report asserts facts where it has no data.** (a) Versions or frameworks absent from the EOL dataset render as "In support" in the deal PDF (reportBuilder.js:161-171, stackReality.js:329-359); a third "Not assessed" status is needed. (b) A failed analyzer renders as zeros in the Executive Summary metrics table ("Total contributors: 0") rather than "n/a" (reportBuilder.js:71-90), and roadmap synthesis runs on partial inputs with no caveat unless all three analyzers failed (roadmapStub.js:64-69). (c) Key-Person Risk silently caps at the most recent 10,000 commits with no disclosure (keyPersonRisk.js:48); original authors of older repos can vanish from a bus-factor analysis presented as whole-history. Fix: three-state support status; n/a cells; cap disclosure footnote. Effort: S each.

**CX-6. Prompt Triage skips exactly the files prompt engineers want audited, silently.** SKIP_BASENAMES drops claude, agents, instructions, cursor, aider, plan, notes, todo (src/prompt-pack/loader.js:56-83), i.e. CLAUDE.md and AGENTS.md, and these skips are not counted in stats.skipped, so a folder of agent instruction files yields "No prompt files found." Also: MAX_FILES=1000 cap is silent; the .github pattern (:112) is dead code (tested against a basename); `_PLAN` catches innocents. Fix: count and print name-based skips with a rename hint, or trim the list. Effort: S-M.

**CX-7. The transport menu (the spend-commitment surface) prices only the first API call.** transport-menu.js:60-85 quotes input x price + one mode-sized output; for Conflict, verification is routinely dominant (the project's own example: scan $0.21, verify $1.78, src/estimator.js:74-80) and narrator/verifier are excluded. "Batch: save 50%" applies only to the scan call since post-processing streams. A "$0.35" commitment can land above $2. Fix: per-mode pipeline line items or an explicit "plus verification/report-writing" qualifier; scope the 50 percent claim. Effort: M.

**CX-8. Compare mode produces meaningless comparisons.** The picker lists every .txt in the reports dir including chat transcripts, Q&A saves, and recon reports; comparing them renders a legitimate-looking "Progress: 0%" summary (compare.js:24-41). Fix: filter to findings-bearing prefixes; warn on zero-findings sides. Effort: S.

**CX-9. Portal Jira export can create tickets for already-fixed findings.** remainingFindings is approximated as the last N baseline findings (portal-publish.js:200-215, acknowledged in-code). Counts are right; the list contents are wrong, and the list is what exports. Fix: persist the already-computed remaining array in project.json and read it verbatim. Effort: M.

**CX-10. GHOST_LICENSE_KEY is named "KEY" but requires the signed token.** A CI-minded Team customer sets the GA- key and gets "Token must have 3 parts, got 1" (store.js:42-50 via validator.js:59-65). Fix: detect the GA- prefix in the invalid branch and explain. Effort: S.

**CX-11. Pending-batch menu rows can wedge as "checking..." forever.** No-API-key and server-side-expired batches render as disabled rows that re-poll on every menu paint and are only removed on successful retrieval (bin/ghost.js:1840-1881). Fix: distinguish states; add dismiss; auto-prune past batch TTL. Effort: M.

**CX-12. Windows menus are visibly degraded.** A ternary-precedence pattern drops descriptions from roughly half the menu entries on Windows only (bin/ghost.js:454-464, 523-526 vs the correctly parenthesized :405-406), and raw Unicode glyphs bypass the SYM abstraction in parse errors, first-run status, and batch output (:160, :170, :237, :2158, :2161, :1800-1811). Fix: parenthesize; route glyphs through SYM. Effort: M.

**CX-13. README sells modes it never describes and quotes prices with no canonical source.** Chat is never mentioned in the README at all; Inheritance Audit (the closer) appears only as a matrix row; Executive Brief and Fix Forecast are undescribed (README.md:365-426 vs :582). Team Max $799 and Enterprise Max $2,500 appear in README (:592, :602-604) but have no keys in src/constants/pricing.js. Fix: add mode descriptions; add TEAM_MAX/ENTERPRISE_MAX to PRICING. Effort: S.

**CX-14. Chat mode has no cost display at all.** The README contract ("cost estimate before every scan and the actual cost after") is implemented in Question mode but absent from Chat, which re-sends full context plus history per turn, potentially the most expensive interactive surface (src/modes/chat.js). Also chat's friendlyError matches any message containing "50" as an API outage (chat.js:35). Fix: first-turn estimate plus running total (streamChat already returns usage); tighten matcher. Effort: S.

## CATEGORY 3: TECHNICAL RISK (ranked by blast radius)

**TR-1. Ghost Watcher posts "Safe to merge" for commits it never scanned.** Blast submission failures are caught non-fatally (watcher-commit.js:1589-1591), BatchAllFailedError and other batch failures clear state and continue (:1647-1653, :1682-1684), and Step 10 then computes clean as allFindings.length === 0 (:2101), posting the green "No findings detected... Safe to merge" PR comment and the "Your codebase is clean" email. Nothing distinguishes scanned-clean from never-ran. A model-name typo in config produces permanent green checkmarks. Fix: track per-scan ran/failed flags; post a distinct "scan incomplete" comment/email (the narratorFailed degraded pattern at :1899-1907 already exists to extend). Effort: M.

**TR-2. POI's "actual cost" is fiction, and the fiction flows into the Enterprise Usage Report.** poi.js:350-352 computes the post-scan "actual cost" line from chars/4 of the single original context plus the final report buffer. Multi-pass POI captures no API usage anywhere (multipass.js:429-460 streams without reading finalMessage().usage; narrator plan/render/patcher calls untracked, narrator.js:1632-1667; LLM-verifier calls untracked, llm-verifier.js:119-133), so N-pass scans with synthesis and verification can be understated 8-10x. meta.cost additionally hardcodes Sonnet rates regardless of model (poi.js:466) and flows via saveReport into appendAuditEvent and getUsageReport (reports.js:258, enterprise.js:529-574): the number an enterprise admin reconciles against their Anthropic bill. Conflict mode already has the correct pattern (real usage into SessionCostTracker with per-stage display); Blast adopted it; POI is the straggler. Fix: port the conflict pattern through callClaudeRaw, narrateReport, and the verifier; replace showActualCost with showConflictCost. Effort: M.

**TR-3. Output truncation is never detected anywhere in the scan pipeline.** No stop_reason check exists after any stream or batch result. Worst case: a merge truncated at its 6,000-token cap silently loses findings from up to 6 passes and the only copy is immediately destroyed (multipass.js:581-597, then pendingPassResults cleared at :1330-1332). Conflict candidate extraction loses whole passes when output is cut mid-fence, and its truncation repair silently discards trailing candidates (conflict.js:232-338). The watcher discards stop_reason during normalization and takes only the first content block (watcher-batch.js:125-139), and its 8096 cap (:1584, likely a typo for 8192) makes this reachable. Fix: check finalMessage().stop_reason === 'max_tokens' after every accumulation; warn visibly; retry/continue merges; surface partial-result markers. Effort: M.

**TR-4. Non-canonical verifier verdicts make findings vanish from every report bucket.** quickVerify passes parsed.verdict through unvalidated (agent/verifier.js:443-449); "confirmed" (lowercase) or any synonym matches no partition (:328-331), so the candidate appears in no section and the stats stop adding up. A real conflict silently disappears from a deal-grade deliverable. Fix: uppercase/trim and validate against the enum, default INSUFFICIENT. Effort: S.

**TR-5. Ghost Mobile contradicts itself on the numbers an exec checks.** (a) Every baseline finding is classified "resolved": mapBaselineFindings preserves ids (mobile-publish.js:126) but parseFindings drops them for current findings (:100-111), so the id-match branch (:158-159) compares against undefined and never matches. (b) Blast/Conflict projects are stuck at 0 percent progress: saveReport builds baselineCount from meta only, never reading storedProject.baselineCount it just loaded (reports.js:305). (c) hasBaseline uses count-equality as identity (mobile-publish.js:139): a rescan landing on the same total reports "no baseline." Fix: keep id in parseFindings; add storedProject fallback; compare baselineDate not counts. Effort: S each.

**TR-6. Watcher resume paths quietly degrade or corrupt state.** (a) Multi-chunk Conflict submits N batches but persists only the first for resume; a died job orphans chunks 2..N and the resumed run reports complete results from a fraction of the codebase (watcher-commit.js:1676-1691, :1424-1439). (b) The prompts-resume path overwrites the portal commit state with findings: [] on the same path Step 8b wrote the real array, so the portal shows a count with an empty list and future delta tracking diffs against nothing (:1391-1399). (c) Resumed blast findings skip narration and file enrichment and are delivered as full-quality results (:1435-1436). Fix: persist all batch ids; merge-preserve state on resume; run blastFindingsFromRaw on resume. Effort: M, S, S/M.

**TR-7. Session resume ignores codebase drift.** Resume restores a pass index into passes rebuilt from the current fileMap with no fingerprint of the original file set (multipass.js:1237-1262, conflict.js:454-481): edit files between sessions and some are scanned twice, others never, while the report claims full coverage. Fix: store a cheap digest (count + bytes + sorted-path hash); warn on mismatch. Effort: S/M.

**TR-8. Loader coverage gaps contradict "If it's code, Ghost reads it."** (a) '.env.example' in CODE_EXTENSIONS is dead: isScannablePath compares path.extname (".example"), so env templates, prime Conflict input, never load (loader/index.js:130, 149-152; verified live). (b) IGNORED_DIRS excludes bare segments setup, var, generated, target, build in any codebase though the comment scopes them to Magento, and the documented --no-default-excludes escape hatch does not exist in bin/ghost.js (loader/index.js:95-116). (c) The same oversized file is truncated-with-marker on directory loads but silently skipped entirely on ZIP/GitHub loads (:722, :755-758 vs :343, :627). Fix: basename check; scope Magento dirs or implement the flag; unify oversize policy. Effort: S/M/M.

**TR-9. Headless paths honor licenses the interactive path blocks.** --watcher-commit and --brief call validateLicense, then getActiveTier without checking isBlocking, so hard_stop/tampered/fingerprint-invalid results still grant tier rights on the two automation surfaces (bin/ghost.js:3161-3178, 3192-3207; session.js:21-24). Flagged as cross-path consistency, not as security. Fix: check isBlocking in both, or have getActiveTier return null for blocking states. Effort: S.

**TR-10. Two paid features are ungoverned by TIER_POLICY, and the paywall payload lies when reached.** Executive Brief has no requireTier anywhere (bin/ghost.js:2721-2813) and no mode:executive-brief entry; WATCH_TIERS is hardcoded twice (:440, :3171), the exact drift class v9.4.3 eliminated for MAX_TIERS. And paywallFor maps every non-audit mode block to kind 'quota' (tier-gates.js:237-251), so a tier-blocked chat or ghost-brief renders "You've used your 4 free Ghost Architect™ reports," false for a new Open user and worse for a paying Pro user. All currently latent (menu hides/disables), but the dispatch gate is the documented enforcement point. Fix: register mode:executive-brief and mode:watch; derive WATCH_TIERS; add a kind:'tier' payload keyed off the verdict reason with accurate copy. Effort: S-M.

**TR-11. Per-pass cost estimates are hardcoded and model-blind at five sites.** $0.25/pass (multipass.js:369, 1279, 1284), $0.30 (conflict.js:104), $0.50 (blast-multipass.js:68), planner.js:88-100 (with a stale pricing comment), $0.01/$0.10 per verify candidate (conflict.js:541-542). None consult getPricing or the model; conflict's pass size scales with tier caps but the constant does not, so the pre-scan quote runs 2x+ low precisely for Enterprise customers on Opus. Fix: one estimatePassCost(passTokens, avgOutput, model) helper in core/estimator.js used everywhere. Effort: M.

**TR-12. 40-character title-prefix matching merges distinct findings and can delete the wrong section.** Dedupe key is title.slice(0,40) (conflict.js:331-338); removeFindingSection builds a first-match regex from the same prefix (verifier.js:804-818), so removing a rejected candidate can delete a verified sibling's section. Fix: normalized full-title (+files) matching. Effort: S.

**TR-13. Transient-failure economics.** Conflict's callClaude has no 529/429 retry (conflict.js:45-77) and nothing checkpoints between the expensive verify phase and narration, so a transient overload discards paid verification work. Blast batch synthesis returns an empty report on expired/canceled results and loses the batch id on timeout (blast-multipass.js:179-207). Fix: port POI's retry ladder; checkpoint verificationResult; throw on non-succeeded with batch id. Effort: M/S.

**TR-14. The corrected-file generator can delete unrelated baseline lines at "high" confidence.** A multi-line patch whose first line matches replaces patchLines.length baseline lines; the common "1 matched line + N insertions" LLM patch shape deletes the N following baseline lines with confidence high and no note (corrected-file-generator.js:232-259). Fix: similarity-check trailing lines or cap confidence with a note. Effort: M.

**TR-15. finding-parser drops data the sidecar consumers rely on.** Extensionless files (Dockerfile, Makefile, Jenkinsfile) and paths with spaces are filtered out of finding.files (finding-parser.js:297-306), weakening portal/Jira/Mobile references and cross-scan ids; EFFORT_RE misses "days"/"minutes" so rollups undercount (:33); SEVERITY_RE misses all-caps lines (:28). Fix: allowlist known extensionless names; extend units; case-insensitive. Effort: S.

**TR-16. Default Watch config ships Ghost's own release-skip heuristic to every customer.** buildWatchConfig emits skip_if_message_contains ['v9.', 'v10.', 'v11.'] (watch/index.js:104-108) with case-insensitive substring matching (watcher-commit.js:1568-1569): a customer commit "upgrade laravel to v10.4" silently skips scanning with no trace. EJ removed these from his own repo in 2cf406b; customers still get them. Fix: default to []. Effort: S.

**TR-17. The test suite overstates its own coverage.** tests/dedup.smoke.mjs fails right now (detector id renamed; verified by running it) and is invisible because it, plus five other substantive suites (banner-promo, commit-forecast, conflict-extractor, verifier-stepcap, assert-prompt-pack), are not wired into npm test. The wired 30-test chain passes clean. tests/ad-hoc/loadFromPath.test.mjs depends on a nonexistent fixture. Fix: fix dedup, wire the five. Effort: S.

**TR-18. Empty-scan-equals-clean in Fix Forecast.** An aborted/failed conflict scan leaves the buffer empty and the mode prints "No conflicts detected in corrected file" (fix-forecast-writer.js:325-344), the same pattern as TR-1. Fix: distinguish no-report from reported-clean. Effort: S.

**TR-19. Public GitHub repo carries internal artifacts (npm tarball is clean).** open/main at v10.0.2 tracks PROMPT_TRIAGE_FOLLOWUPS.md (internal planning), prompts-extracted/ (system-prompt snapshots), ghost-watcher.yaml (personal email), audit-reports/, fix-456.mjs, test-agent.js, .ghost-notes, and a tracked node_modules symlink to a local path. .gitignore is a no-op for already-tracked files.
